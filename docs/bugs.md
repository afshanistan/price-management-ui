# Known bugs

Found while reviewing; fix in a bug pass. Newest first.

- [ ] **The wizard doesn't fit a short laptop window; Back / Next fall off the bottom** · Every step, page layout (WizardLayout) · On Will's MacBook in Chrome (window ~765px tall with tabs and bookmarks bar), the card's bottom and the footer buttons are cut off. **Cause:** the layout was set for 1440×900, checked at 1280×800 (decision log, "Page layout"): header 56 + stepper band 80 + fixed 644 card + 24 gap + 56 footer is ~860px tall. **Fix options (Will to pick at the bug pass):** (A, Claude's pick) the card shrinks to fit the window below its 644 (`min(644px, available height)`); its body already scrolls, so Next stays visible and still never moves between steps; no change at 900. (B) Compact spacing on short windows (smaller stepper band and gaps under ~820px tall), on its own or with A. (C) Pin the footer to the window bottom: not recommended, it brings back the "orphaned buttons" the decision log rejected. **Workaround for demos:** Chrome full screen (View → Enter Full Screen), plus zoom to 90% if needed. Will, Oct 20

- [x] **Escape in the brand search wiped every selected brand** · Step 2, Select brands card (and the step 1 Results panel) · With the search empty, Escape cleared the whole selection (24 → 0), with no undo. **Cause:** React Aria's ListBox clears its selection on Escape by default, and the search passes Escape on to it. On step 1 the same default made Escape look like "re-picking" vendors. **Fixed Oct 18:** `escapeKeyBehavior="none"` on the Brand list and the Results panel; the step 2 flow test now presses Escape twice and checks the picks are kept. Found by the steps 2–4 pressure test

- [x] **Results panel paints under the Selected vendors area** · Step 1, Select vendors card · Typing "co": the "Selected vendors (0)" label and the empty state show through the open Results panel. **Likely cause:** the page-load animation (Step 1 motion pass, Oct 18). Each staggered group (`.select-vendors-card__search`, divider, `__selected`) gets its own stacking context while `motion-enter` holds its end state (`animation-fill-mode: both`), so the panel's `z-index: 1` only counts inside the search group, and the later selected area paints on top. **Likely fix:** drop the forwards fill (use `backwards`, so the animation releases when it ends), or give the search group a higher stacking order than the groups after it. Will, Oct 18. **Fixed Oct 18:** page-load animations use `backwards` (motion bug pass)
